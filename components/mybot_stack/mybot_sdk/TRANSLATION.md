# S31 translation SDK

This is a project-maintained fork of the recorded MyBot SDK baseline. Media uses `v2vt/listen`; face-to-face and Mosaico meetings use `v2vt/listen_speak`. Media/face-to-face route the board microphone and speaker. Meetings send platform USB capture to LISTEN and physical MIC to SPEAK, play LISTEN on the board speaker and return SPEAK through platform USB playback. USB device ownership and resampling remain in the platform. There is no assistant backend.

- `mybot_config_t` provides initial source and target language codes. Device language selections persist in KV. In media mode these mean input/output (`remote_language`/`local_language`). In face-to-face mode they mean my/partner language (`local_language`/`remote_language`); listen translates partner to local, speak translates local to partner. Mode is volatile and defaults to listen after boot.
- Start requests preserve G.722, 60 ms, cloud AEC and AI QoS settings and select `translation.mode=listen` or `listen_speak`. Returned routes are normalized to listen then speak, with separate credentials and four distinct device/Agent identities in face-to-face mode. Both directions must share the App ID, channel and expiry; the top-level RTC compatibility view is ignored. Caption-only listen is valid; speak always requires TTS.
- AI QoS defaults to disabled in both firmware configuration and the SDK fallback. It can be enabled explicitly with `CONFIG_MYBOT_AI_QOS=y`; when disabled, start sends `ai_qos=false` without a fast-send multiplier and RTC leaves AI QoS disabled.
- Start preflight requires a usable UTC clock before HTTP; `TIME_NOT_SYNCED` is a local rejection and permits retry after synchronization. The platform can initialize UTC from SNTP or a verified HTTPS response Date header; route expiry remains mandatory. Translation start has one shared 30-second HTTP deadline; other requests retain their 5-second deadline, with no automatic start retry.
- Cloud AEC retains the existing 16 kHz mono S16 contract, paired MIC/reference layout and `pcm_channel_num=1`. Speaker output and MIC upload remain concurrent. In meetings, SPEAK pairs physical MIC with the speaker reference; USB LISTEN pairs PC audio with zero reference. No local AEC algorithm was added.
- UI volume and volume adjustment read the same active output channel: hardware volume when initialized, otherwise software media volume. A failed hardware read displays an unknown value and retries on later control ticks; it never substitutes the software unity gain for a failed hardware read.
- `<mybot/mybot_ui.h>` exposes one immutable 15-language list and copied, asynchronous mode/language/direction/absolute-volume/pause commands. Submission never waits for lifecycle or mailbox admission; the mailbox holds at most eight values. Accepted commands can still be rejected by the control owner when state changes. Platforms read LCD content for actual results. Mode and language changes require idle state, including no queued start or pending cleanup. Language pairs commit together to one KV record; a failed write preserves the previous pair and blocks new starts until storage is recovered.
- Pause is local to an active RTC session. The media workers retain the 60 ms cloud-AEC MIC/reference cadence while suppressing source content and translated playback. Resume discards buffered audio before playback restarts. LCD `paused` reflects the media gate, including driver failures. An incomplete local end-session keeps a recovery flag; subsequent starts must recover playback before any cloud start is requested, otherwise `MEDIA_NOT_READY` is returned to the display.
- RTC disables automatic audio subscription. Each returned publisher account is resolved on its own connection, explicitly subscribed and checked before any PCM reaches playback. Readiness requires every RTC join and every enabled TTS publisher subscription. Connection readiness and reconnect recovery have a 15-second limit. Any required Agent going offline stops the whole parent session.
- Each conversation owns a fresh RTSA service and callback queue. Ending it finalizes both, so the next conversation can use another Bot project's App ID. A successful global RTSA finalization completes cleanup even if an intermediate leave/destroy failed. A retained callback queue is cleaned before another cloud start; failed cleanup reports `RTC_NOT_READY`. A vendor global-finalization failure requires a device restart and is never retried against a partially finalized vendor service.
- Face-to-face creates both RTC identities under one parent and initially selects no microphone direction. Every 60 ms, the selected route receives MIC and the other receives zero MIC; both retain the same physical playback reference when cloud AEC is enabled. The reference is consumed once from the existing pipeline. Direction changes fence producers and flush old PCM through pause/resume; only the selected route's translated PCM reaches the speaker. Both directions' captions continue to merge independently. No HTTP request occurs during a direction change. Silent frames do not guarantee that the cloud Agent's idle timeout is extended.
- Start HTTP runs on the service worker. The control owner handles configuration, cancellation and results. All results first enter an owned mailbox, including results arriving during shutdown.
- A durable journal blocks a new start until the previous parent is confirmed ended. It also records an unknown start before issuing HTTP, allowing fail-closed recovery after power loss. There is no service query endpoint for an unknown parent ID; service reconciliation is required for that case.
- Stop retries retain the original service, device, credential and parent identity. Credentials expiring end the session; no translation renewal endpoint is assumed.
- The pinned RTSA service has one RTM login. All modes log in with the listen UID/token and subscribe to the shared channel once. Face-to-face and meetings rely on both Agents publishing captions into that channel; they do not attempt a second RTM login. Direct messages received by the logged-in identity remain accepted. Sender identity maps to the returned listen/speak route; other senders, channels, old session generations and assistant-command payloads are ignored.
- `user.transcription` and `user.translation` JSON events merge by `(direction, stream_id, turn_id)`. The trusted direction comes from the route Agent, never the selected microphone button or a payload field. Each side accepts interim replacements, including shorter revisions, and preserves final text against late interim updates. When both `start_ms` and `duration_ms` are available, an older end time is rejected; missing or equal times use arrival order. Translation-first events can supply the original through `transcript_text`. `final` finalizes text only and never stops the session.
- Caption callbacks enqueue at most eight copied messages, each at most 8 KiB; overflow retires the oldest queued message. The control owner parses and merges them into a PSRAM-backed ring of the latest 64 sentence pairs. Each side retains up to 1,023 UTF-8 bytes, truncates at a character boundary and reports truncation. Stop preserves this session's retained text; the next accepted session resets it. Pause continues accepting already-produced text.
- `<mybot/mybot_captions.h>` exposes nonblocking, copied sentence reads by generation and sequence. LCD snapshots carry only small revision/count/sequence metadata, including the latest retained sequence for each direction; zero means that direction has no retained record. A busy, reset or evicted read returns failure without changing the caller's output. The realtime, full-text and session-history pages share this single ring; records are not persisted across device restart.

Run `tests/translation_{client,lifecycle,rtc,control,state,ui,volume,captions}/run.sh` individually for host protocol, ownership, failure, caption and UI checks. These tests do not establish physical audio/AEC quality or successful service interoperability.
