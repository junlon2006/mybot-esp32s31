# S31 listen translation SDK

This is a project-maintained fork of the recorded MyBot SDK baseline. It supports only a standalone `v2vt/listen` session: board MIC input, RTC upload, translated RTC audio and board speaker output. There is no assistant backend or USB audio path.

- `mybot_config_t` provides initial source and target language codes. Device language selections persist in KV. `translation.remote_language` is the input; `translation.local_language` is the output.
- Start requests preserve G.722, 60 ms, cloud AEC and AI QoS settings and add `translation.mode=listen`. Only the returned listen route is accepted; the top-level RTC compatibility view is ignored.
- Start preflight requires a usable UTC clock before HTTP; `TIME_NOT_SYNCED` is a local rejection and permits retry after synchronization. The platform can initialize UTC from SNTP or a verified HTTPS response Date header; route expiry remains mandatory. Translation start has one shared 30-second HTTP deadline; other requests retain their 5-second deadline, with no automatic start retry.
- Cloud AEC retains the existing 16 kHz mono S16 contract, paired MIC/reference layout and `pcm_channel_num=1`. Speaker output and MIC upload remain concurrent. No local AEC algorithm was added.
- UI volume and volume adjustment read the same active output channel: hardware volume when initialized, otherwise software media volume. A failed hardware read displays an unknown value and retries on later control ticks; it never substitutes the software unity gain for a failed hardware read.
- `<mybot/mybot_ui.h>` exposes one immutable 15-language list and copied, asynchronous language/absolute-volume/pause commands. Submission never waits for lifecycle or mailbox admission; the mailbox holds at most eight values. Accepted commands can still be rejected by the control owner when state changes. Platforms read LCD content for actual results. Language pairs commit together to one KV record only while idle; a failed write preserves the previous pair and blocks new starts until storage is recovered.
- Pause is local to an active RTC session. The media workers retain the 60 ms cloud-AEC MIC/reference cadence while suppressing source content and translated playback. Resume discards buffered audio before playback restarts. LCD `paused` reflects the media gate, including driver failures. An incomplete local end-session keeps a recovery flag; subsequent starts must recover playback before any cloud start is requested, otherwise `MEDIA_NOT_READY` is returned to the display.
- RTC disables automatic audio subscription. The returned publisher account is resolved to its numeric UID, explicitly subscribed and checked before any PCM reaches playback. The required Agent going offline stops the session.
- Each conversation owns a fresh RTSA service and callback queue. Ending it finalizes both, so the next conversation can use another Bot project's App ID. A successful global RTSA finalization completes cleanup even if an intermediate leave/destroy failed. A retained callback queue is cleaned before another cloud start; failed cleanup reports `RTC_NOT_READY`. A vendor global-finalization failure requires a device restart and is never retried against a partially finalized vendor service.
- Start HTTP runs on the service worker. The control owner handles configuration, cancellation and results. All results first enter an owned mailbox, including results arriving during shutdown.
- A durable journal blocks a new start until the previous parent is confirmed ended. It also records an unknown start before issuing HTTP, allowing fail-closed recovery after power loss. There is no service query endpoint for an unknown parent ID; service reconciliation is required for that case.
- Stop retries retain the original service, device, credential and parent identity. Credentials expiring end the session; no translation renewal endpoint is assumed.
- RTM login and channel subscription remain required. Subtitle and assistant-command payloads are ignored.

Run `tests/translation_{client,lifecycle,rtc,control,state,ui,volume}/run.sh` individually for host protocol, ownership, failure and UI checks. These tests do not establish physical audio/AEC quality or successful service interoperability.
