# Mosaico translation UI

The only supported target is ESP-Mosaico CoreBoard V1.2 with a native 480×480
LVGL layout. Scene cards stack vertically; language settings keep two columns;
captions use the available width; face-to-face retains two language buttons at the
bottom. The layout keeps 20/28/40 px fonts and touch regions at least 44×44 px.
The top status labels stay 60 px from either side and body controls 32 px from the
sides, with bottom controls lifted out of the rounded corners. The home action uses
one line. Display, touch, shared I2C and framebuffers remain owned by the board drivers.

The UI shows actual Wi-Fi, system time and output volume, with placeholders before
time synchronization. Its volume slider spans the screen width. Battery and
brightness placeholders are not part of the product UI. Pairing, provisioning,
confirmation, caption history and full-text pages also use the native panel width.

If USB initialization does not provide capture/playback capabilities, the meeting
card shows "USB unavailable" and is disabled. Meeting setup and language submission
also require that capability; their labels always use SDK language readback.
An initialized USB device whose host stream is not open still uses the existing
USB_AUDIO_NOT_READY start response.

Media translation uses the real `v2vt/listen` microphone-to-cloud-to-speaker path, initially Chinese to English. Face-to-face uses `listen_speak`: choose my/other languages, start one parent session, then select a language button to open the microphone direction. Two RTC connections share one RTM login and channel subscription. Meetings use listen_speak with both directions active concurrently: PC audio goes to LISTEN and its translation plays on the device speaker; the physical microphone goes to SPEAK and its translation returns through USB input to the PC. My language is local (initially Chinese); the other language is remote (initially English). The live page follows the latest caption from either direction, shows its language route, and pauses both paths without turn-selection buttons. Live captions, full text and session history share original/translated text received through the two trusted Agents' RTM messages. Defaults remain Chinese input to English output for media and Chinese as my language / English as the other language for face-to-face.

Face-to-face initially shows no selected direction. The language buttons select speak (my language) or listen (other language); selection remains locked until the SDK acknowledges it. Direction changes fence and clear local PCM before resuming, and only the selected direction reaches the speaker. The selected Local or Cloud AEC mode keeps capture and playback concurrent. The UI does not infer speech completion from caption final flags or timers.

The home/scene/settings/language/live/menu/confirmation/completion/error pages follow SDK lifecycle snapshots. The completion page provides back-to-home, session-history, translate-again and change-scene actions. A queued command never fabricates a successful connection. Active language changes require confirmed session teardown. Cleanup and unknown outcomes continue to block new sessions; late start success after cancellation leaves a usable stop/retry action. Definite start errors and failed local media recovery remain visible.

`mybot/mybot_ui.h` exposes the shared 15-language list and bounded, nonblocking commands copied by value. Language, mode, direction, volume and pause commands pass touch-gesture validation in the input router, then submit directly to the SDK mailbox without blocking and check admission. Start and stop key events are forwarded by the existing input worker. The SDK control owner validates and applies all commands. An accepted language pair locks both language selectors and start until that pair is read back or an actual failure occurs; unrelated volume snapshots and the local retry timer cannot unlock it. Mode and direction commands have a small completion revision, so unrelated volume/caption refreshes cannot acknowledge a failed retry. A rejected submission can be retried immediately. A released volume drag commits once, and confirmed volume/pause/language values come from LCD snapshots. The Mosaico AI button is reserved for provisioning and factory reset.

Local pause preserves capture and the RTC parent session, sends silent MIC frames at the existing 60 ms cadence, and stops playback independently to clear driver-owned PCM. Only Cloud AEC uses the paired MIC/reference transport; default Local AEC supplies cleaned mono PCM during normal operation. Capture fences synchronously clear the backend's partial AEC input, pending output and filter history before acknowledging pause/resume or a direction change. Reset failure keeps media closed until capture stop/start recovery succeeds. Resume clears stale PCM and restarts playback before confirming success. Hardware volume is preserved; pause is not a cloud session stop.

With no text, the live page displays a waiting hint. Original and translated interim text revise independently until final. Face-to-face Live follows the selected direction; both directions share one 64-entry ring keyed by direction/stream/turn, and history/full text show the sentence’s language direction. Tapping a caption opens scrollable full text; session history pages through the latest 64 sentence pairs without jumping to newly received sentences. Each side holds up to 1,023 UTF-8 bytes and marks truncation. Pause accepts already-produced text. Stop preserves this session's history and the completion page provides a history action; the next accepted session clears it. History is held in PSRAM and does not survive restart. Messages from other senders/channels and old sessions are rejected.

The view uses generated 20/28/40 px Noto Sans SC UI subsets and separate 2 bpp caption fonts. The 20 px font covers all 6,763 GB2312 Han characters, JIS X 0208, non-private-use CP932 extensions, modern and halfwidth kana, Latin-1 and Chinese/Japanese punctuation. Combining kana voicing marks use zero advance and overlay the preceding kana. The 28 px font covers printable ASCII, Latin-1 and typographic punctuation and falls back to 20 px for other included characters. Both use LVGL row-XOR RLE without changing the four alpha levels, within a 1 MiB font-data budget. Chinese, English and Japanese have glyph coverage; other audio languages do not imply complete multilingual glyph coverage or shaping. Unavailable and private-use glyphs display placeholders. All fonts retain OFL notices, with no browser runtime or online asset dependency. Host UI checks run at 480×480 with Chinese and English text. Every click and state update checks child bounds, disjoint sibling touch regions and minimum touch size. Square-panel labels and controls are also checked against 64 px rounded corners, with a 60 px inset for the status strip. The user confirmed normal captions with 40-row buffers and basic meeting translation; touch/start requests have device logs. Later input/language/recovery fixes have host/build coverage only, while detailed service-message and pause behavior still need device acceptance.
