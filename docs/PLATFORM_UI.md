# Mosaico translation UI

The current target is ESP-Mosaico CoreBoard V1.2 with a native 480×480 LVGL layout. Scene cards stack vertically; language settings keep two columns; captions use the available width; face-to-face retains two language buttons at the bottom. The layout keeps 20/28/40 px fonts and touch regions at least 44×44 px instead of scaling down the wide screen. Mosaico keeps the top status labels 60 px from either side and body controls 32 px from the sides, with bottom controls lifted out of the rounded corners. Its home action uses one line. The shared view also supports the existing 800×480 Korvo panel. Display, touch, shared I2C and framebuffers remain owned by the board drivers.

Mosaico shows actual Wi-Fi, system time and output volume, with placeholders before time synchronization. Its volume slider spans the screen width. The unused battery indicator and brightness demonstration are omitted on this target; Korvo retains those older placeholders. Pairing, provisioning, confirmation, caption history and full-text pages also use the native panel width.

Media translation uses the real `v2vt/listen` microphone-to-cloud-to-speaker path, initially Chinese to English. Face-to-face uses `listen_speak`: choose my/other languages, start one parent session, then select a language button to open the microphone direction. Two RTC connections share one RTM login and channel subscription. Meeting provides a settings preview with disabled start. Live captions, full text and session history share original/translated text received through the two trusted Agents' RTM messages. Defaults remain Chinese input to English output for media and Chinese as my language / English as the other language for face-to-face.

Face-to-face initially shows no selected direction. The language buttons select speak (my language) or listen (other language); selection remains locked until the SDK acknowledges it. Direction changes fence and clear local PCM before resuming, and only the selected direction reaches the speaker. Existing cloud AEC keeps capture and playback concurrent. The UI does not infer speech completion from caption final flags or timers.

The home/scene/settings/language/live/menu/confirmation/completion/error pages follow SDK lifecycle snapshots. A queued command never fabricates a successful connection. Active language changes require confirmed session teardown. Cleanup and unknown outcomes continue to block new sessions; late start success after cancellation leaves a usable stop/retry action. Definite start errors and failed local media recovery remain visible.

`mybot/mybot_ui.h` exposes the shared 15-language list and bounded, nonblocking commands copied by value. Language selection submits directly through this public interface to check admission; volume, pause and key events retain the existing input worker. The SDK control owner validates and applies all commands. An accepted language pair locks both language selectors and start until that pair is read back or an actual failure occurs; unrelated volume snapshots and the local retry timer cannot unlock it. Mode and direction commands have a small completion revision, so unrelated volume/caption refreshes cannot acknowledge a failed retry. A rejected submission can be retried immediately. A released volume drag commits once, and confirmed volume/pause/language values come from LCD snapshots. Physical key handling belongs to the selected board; the view forwards through its input worker.

Local pause preserves capture and the RTC parent session, sends silent MIC/reference frames at the existing 60 ms cadence, and stops playback independently to clear driver-owned PCM. Resume fences workers, clears stale data and restarts playback before confirming success. Hardware volume is preserved; pause is not a cloud session stop.

With no text, the live page displays a waiting hint. Original and translated interim text revise independently until final. Face-to-face Live follows the selected direction; both directions share one 64-entry ring keyed by direction/stream/turn, and history/full text show the sentence’s language direction. Tapping a caption opens scrollable full text; session history pages through the latest 64 sentence pairs without jumping to newly received sentences. Each side holds up to 1,023 UTF-8 bytes and marks truncation. Pause accepts already-produced text. Stop preserves this session's history and the completion page provides a history action; the next accepted session clears it. History is held in PSRAM and does not survive restart. Messages from other senders/channels and old sessions are rejected.

The view uses generated 20/28/40 px Noto Sans SC UI subsets and separate 2 bpp caption fonts. The 20 px font covers all 6,763 GB2312 Han characters, Latin-1 and common Chinese/English punctuation. The 28 px font covers printable ASCII, Latin-1 and typographic punctuation and falls back to 20 px for Chinese. This first font set targets Chinese-to-English captions; the 15 audio languages do not imply complete multilingual glyph coverage or shaping. Unavailable glyphs display placeholders. All fonts retain OFL notices, with no browser runtime or online asset dependency. Host UI checks run both native dimensions with Chinese and English text. Every click and state update checks child bounds, disjoint sibling touch regions and minimum touch size. Square-panel labels and controls are also checked against 64 px rounded corners, with a 60 px inset for the status strip. Input, lifecycle, caption, mailbox, audio and pause tests check behavior and ownership; actual service messages, panel/touch/audio behavior require device acceptance.
